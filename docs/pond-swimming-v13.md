# 安静水池与游泳 v0.13

## 当前调整 v0.13.1：少量大波纹与白色浪花

按最新反馈，把过弱的细波纹调整为较大、较清楚的断续浪纹。游动时约每 0.72 秒、实际移动超过 0.1 米后发出一道，单道存活 1.35 秒，通常同屏一至两道，最多三道。弧线有缺口、宽度与轮廓变化，避免形成完整的指示圆环。

身体两侧增加与划水周期交替变化的白色小浪花，停下后淡去。底层排水足迹加宽、强度略增，保留原有真实波动与轻微折射。没有改模型或游泳动作。

最新预览：renders/swimming-v13.1-foam.webm。test:swimming 额外检查移动时有白色浪花、浪纹数量受限，以及停下、暂停、场景切换时的清理。

以下记录 v0.13 的初始设计；涉及波纹样式的部分以上述最新调整为准。

采用已确认的方向：B 的物体扰水，A 的简化卡通配色，C 的动作与水面衔接。随后按用户要求降低波幅与高光，保持安静小池塘的感觉。

- B：[Three.js Water](https://github.com/jeantimex/threejs-water)。直接采用并适配 MIT 的 WaveSimulation、WaterNormal、WaterRipple 和 CompoundSphereDisplacement GLSL。保留全部上游原始着色器和许可在 src/vendor/ 与运行包 fx/vendor/。
- A：[Cortiz Water Anime](https://stylized.cortiz.dev/water)。仅参考卡通表现层次，不移植硬边圆环或 Voronoi 白色纹理。
- C：[Nintendo 官方游泳演示](https://www.youtube.com/watch?v=jO0luDEHesc)。参考起停、入水与水花的衔接，不使用其动画资产。

## 当前画面

水面平时安静，没有周期性白圈、整圈白岸线或直线 V 形尾迹。身体、头部和四肢的骨骼接触代理改变位置时排开水体，波纹通过 GPU 高度场传播、叠加、衰减；岸边吸收波浪。游动波高控制在几毫米量级，本机样例峰值约 3 毫米。入水只产生四颗小水滴与很轻的扰动。

水面几何实际随波高起伏，光线变化来自高度场法线。屏幕空间颜色与深度缓冲为水下身体、石子提供轻微折射，扭曲幅度已降低；不是照搬 B 的整套光线追踪或强焦散。没有新增花纹贴图或水面炫光。

## 动作

Swim 身体前倾约 10°，SwimIdle 约 6°；抬头少量补偿以保持表情可见。四肢由 IK 烘焙，约 42% 周期用于向后划水，其余时间收腿回摆；尾鳍展开并小幅摆动。取消固定的上下正弦弹跳，浮沉使用阻尼响应。

游动速度约 0.65 米/秒，推进有轻微节奏变化，转向约 2.8 弧度/秒；起步、减速、转向均有缓冲。身体基点在水面以下 0.19 米。入水抛物线高度从 6.5 厘米收小到 2.5 厘米。点击水面游动、点击草地上岸、水中喷水和先上岸再吃果子的操作不变。

源模型：mudkip-toon-v13-swimming.blend，规范源：game-assets/source/mudkip-animations.blend。

## 实现与开销

- src/pond-simulation.js：适配上游双缓冲模拟，每步 1/120 秒；移动体积按固定步长扫过，避免慢帧留下分段脚印。桌面 96²、初始手机视口 64²，HalfFloat 缓冲。
- src/pond-water.js：卡通水面、细分网格、折射与小水滴；折射缓冲为屏幕的 65%，宽度上限 960 像素。
- src/garden-swimming.js：转向、起停、阻尼浮沉；main.js 将真实骨骼位置传给水面。
- 总共两个小模拟缓冲与一个颜色/深度折射缓冲。暂停冻结模拟，场景切换清空。日常渲染没有 GPU 像素回读；sampleWaves 仅供 QA。
- 手机检查使用桌面浏览器的移动视口及触控模拟；这不能代表具体手机的真实帧率。
