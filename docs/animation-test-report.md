- 日期：2026-11-03
- 目标：验证原模型蒙皮是否可用、Blender 动作能否完整导出，以及 Three.js 能否正确播放、混合和驱动位移。
- 结果：最小角色动画管线已跑通。

## 动作与骨骼

| Action 名 | 时长 | 播放方式 | 内容 |
| --- | --- | --- | --- |
| `Idle` | 3.0 秒 | 循环 | 轻微呼吸、头鳍和尾巴摆动 |
| `Walk` | 0.8 秒 | 循环 | 四足错相小步走，抬脚与接地，身体轻微起伏 |
| `PetReaction` | 1.6 秒 | 单次 | 轻轻蹲下、抬头歪头、开心摇尾，随后回待机 |

保留原来的 24 根蒙皮骨骼，新增一个 `MotionRoot`，统一控制原本独立的 Hips 与 Spine1。没有改动原角色的拓扑、UV 或原始贴图。

四肢通过解析两段 IK 计算逐帧姿势，然后烘焙为普通骨骼关键帧，GLB 运行时不依赖 Blender 约束。身体起伏时保持脚掌接地，走路阶段再沿周期抬脚。

动作按 30 fps 采样，Blender 帧范围分别为 1–91、1–25、1–49；导出时将时间起点平移至 0，避免浏览器开头多出一帧等待。

## 验证结果

- 原蒙皮 1,676 个顶点全部有权重，逐顶点权重和约为 1。
- Blender 中两段循环的首尾顶点差为 0；四肢目标均在可达范围内。
- GLB 导出 25 根骨骼、三段动画、两张 256 × 256 PNG 贴图。
- Khronos glTF Validator：0 错误、0 警告。
- Three.js 实际载入并验证了三段动画时长、骨骼和 sRGB 贴图。
- 骨骼动作在浏览器中实际改变了蒙皮顶点，未发现坐标爆炸。
- 循环首尾误差小于 0.0001 米，水平根位移为 0。
- 测量走路接地段的脚掌运动，和代码位移速度吻合；默认速度约 0.2621 米/秒。
- 验证了按钮切换、0.22 秒混合、连续快速切换、暂停、拖动进度与恢复。
- 验证了直接点击三维角色触发回应、生成三颗爱心、动作结束后回待机。
- 验证了点击三维地面设置目标、实际移动到目标、变速时同步步频与位移。
- 桌面 1440 × 1000 和窄屏 390 × 844 均检查布局与截图。窄屏是桌面浏览器视口模拟，并非手机硬件实测。
- 浏览器控制台与请求检查见 JSON 报告；生产构建通过。

## 接入约定

- Three.js：`+Y` 向上，角色前方为 `+Z`。
- Blender 只负责身体骨骼动作。Three.js 移动与旋转包住整个 GLB 场景的角色容器。
- `Walk` 无水平根位移。运行时代码的默认速度使用 `0.13 / (0.8 × 0.62)`，再乘步频倍率。接地比例已计入，避免把接地行程误当作整周期位移。
- `Idle` 和 `Walk` 使用 `LoopRepeat`；`PetReaction` 使用 `LoopOnce`，结束后回到 `Idle`。
- 爱心属于 Three.js 运行时精灵，不写入角色 GLB。
- 导出模式为 `ACTIONS`，开启蒙皮、逐帧采样、时间起点归零与 Y-up 转换，只导出角色。
- GLB 的蒙皮网格和骨架均为场景根节点，由同一个外层容器整体驱动。Blender 中网格通过 Armature modifier 关联骨架。

## 当前边界和下一步

这三段是验证工作流的首版动作，动作节奏和表情仍可根据试玩继续调整。测试使用独立舞台，没有接入现有庭院，也没有实现地形碰撞或寻路。

下一步可以把庭院整理为 `garden.glb`，替换不便导出的程序材质，补充地面点击区域与障碍碰撞，再将本次角色容器直接放入庭院。喂食、蓄力、喷水等动作可沿用相同的 Actions → GLB → AnimationMixer 流程。
